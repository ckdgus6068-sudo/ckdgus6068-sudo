# 젤리 캘린더 (Jelly Calendar)

삼성 갤럭시에서 쓰는 안드로이드 캘린더 앱입니다. 할 일을 시간 길이만큼의 말랑한 “젤리”로 만들어 요일 칸에 자유롭게 넣고, 그날 못 한 젤리는 화면 아래 보관함에 모았다가 주말 같은 다른 날로 옮겨 채웁니다.

## 주요 기능

- **젤리 블록**: 길이(시간)만큼 크기가 정해지는 블록입니다. 가만히 있을 때는 숨 쉬듯 살짝 출렁이고, 누르면 눌리며, 끌고 가면 손가락 반대쪽으로 늘어졌다가 놓는 순간 “퐁” 하고 튕기며 자리를 잡습니다.
- **세 가지 탭**: 맨 위 ‘내 젤리 · 공유 젤리 · 모두’ 탭으로 무엇을 볼지 고릅니다. ‘내 젤리’는 이 휴대폰에만 있는 일정, ‘공유 젤리’는 정한 사람들과 함께 쓰는 달력, ‘모두’는 내 젤리와 모든 공유 달력을 합친 화면입니다.
- **아래쪽 막대**: 어느 화면에서든 왼쪽 ‘오늘’은 오늘로, 오른쪽 ‘+’는 새 젤리로 갑니다. 가운데에서 ‘상자 · 주 · 일 · 달’ 보기를 고릅니다. 공유 화면(아이폰 포함)도 같은 막대를 씁니다.
- **상자 보기**: 하루를 검은 상자 하나로 보여 줍니다. 그날의 젤리가 시작 시간 순서대로 위에서 떨어져 서로 눌리며 쌓이고, 오래 걸리는 일일수록 젤리가 큽니다. 앱을 열면 이 화면이 먼저 나옵니다.
- **주간·일간·월간 보기**: 주간과 일간은 시간표입니다. 월간(‘달’)은 하루에 할 젤리를 세 개까지 보여 주고, 다 먹은 젤리는 달력 칸에서 빼서 아래 그날 목록에 접어 둡니다. 한 주는 일요일부터 시작하며 설정에서 월요일로 바꿀 수 있습니다.
- **공휴일**: 2025–2030년 대한민국 공휴일(설날, 추석, 개천절, 한글날, 대체공휴일, 선거일 등)을 빨간 날짜와 이름으로 보여 줍니다. 표는 `tools/make_holidays.py`가 Python `holidays` 패키지에서 만들어 앱과 웹에 함께 넣습니다.
- **젤위로 고정**: 중요한 젤리를 상자 맨 위에 핀으로 꽂아 둡니다. 하루 세 개까지이고, 다른 젤리는 그 아래로 흘러내립니다. 고정된 젤리도 핀에 매달린 채 살랑살랑 흔들리고, 누르면 출렁이며, 끌어당기면 쭉 늘어났다가 제자리로 돌아옵니다. 공유 젤리에도 됩니다.
- **내 캐릭터**: 젤리에 눈과 입을 달고 직업 옷이나 모자를 입힙니다. 직업은 스무 가지(경찰관, 소방관, 의사, 간호사, 판사, 변호사, 교사, 회사원, 요리사, 군인, 농부, 건설 기술자, 택배 기사, 운전기사, 개발자, 디자이너, 미용사, 바리스타, 연구원, 학생)이고, 직업마다 표정과 옷이 다른 두 가지가 있어 같은 직업을 고른 사람끼리도 구별됩니다. 공유 달력에서는 각자 고른 캐릭터가 그 사람이 올린 젤리와 동그라미에 쓰이고, 설정의 ‘내 젤리에도 입히기’를 켜면 상자 속 내 젤리도 입습니다. 그림은 `jelly-calendar/share/looks/looks-src.mjs` 한 곳에서 그리고, `build-looks.mjs`가 웹(`docs/share/looks.js`)과 앱(`LookBook.kt`)에 같은 모양으로 넣습니다.
- **새 젤리 빚기**: 무엇을 할지, 맛(색), 길이, 언제를 먼저 정합니다. 길이는 젤리를 오른쪽으로 쭉 당겨 정하며, 두 시간까지는 10분, 그 뒤로는 30분씩 스물네 시간(하루)까지 늘어나고 칸마다 진동으로 손맛을 줍니다. 야간 근무나 당직처럼 자정을 넘기는 젤리는 ‘18:00–다음 날 09:00’으로 표시되고, 다음 날 주·일 시간표 맨 위에 ‘↳ 어제부터’로 이어서 그려지며, 끝나는 날이 지나야 보관함으로 갑니다. 겹침 검사와 빈 시간 추천도 앞뒤 날까지 봅니다. 상자에서는 열두 시간이 넘어도 더 커지지 않습니다. ‘더 보기’에 고정, 시작 전 알람, 반복, 보관함 규칙, 메모가 있습니다. 이름에 ‘11시 미용실’, ‘오후 3시 반 회의’, ‘19:30 영화’처럼 시각을 쓰면 새 젤리의 시간이 그 시각으로 맞춰지고(직접 시간을 고치면 더는 따라가지 않음), 이미 있는 젤리에는 ‘제목대로 11:00’ 버튼이 나옵니다. 오전·오후가 없으면 1~6시는 오후, 7~11시는 오전으로 보되, 이름에 ‘저녁’, ‘밤’, ‘아침’, ‘새벽’, ‘기상’이 있으면 그에 따릅니다. ‘1시간’처럼 길이를 뜻하는 말은 시각으로 보지 않습니다. 공유 달력도 같은 규칙입니다(`TitleTime.kt`, `docs/share/titletime.js`, 같은 문장으로 시험).
- **보관함**: 하루가 지나도록 다 먹지 못한 젤리는 화면 아래 보관함으로 내려가고, 원래 자리에는 “놓침” 자국이 남습니다. 보관함 젤리를 날짜 칸이나 상자, 달력에 놓으면 “언제 먹을까요?” 하고 물어서 원래 하려던 시간, 그날 비어 있는 시간 세 개, 직접 고르기 가운데 하나를 고르게 합니다. 시간표의 원하는 칸에 바로 놓을 수도 있습니다.
- **다 먹었어요**: 젤리를 두 번 톡 하거나 꾹 눌렀다 떼면 다 먹은 젤리가 됩니다. 아래에서부터 진한 색이 물처럼 차오르고 체크 표시가 붙습니다. 한 번 더 하면 되돌아갑니다.
- **반복 젤리**: 매일, 평일, 주말, 또는 원하는 요일마다 같은 시간과 길이로 자동으로 깔리는 젤리입니다.
- **삼성 시계 연동**: 기상 알람과 첫 일과를 맞추고, 젤리마다 시작 전 알람(정각, 10분 전, 30분 전)을 맞춥니다. 아래 “삼성 시계 연동 방식과 한계”를 참고해 주세요.
- **글씨체**: 기본값 “동글”은 젤리 이름과 제목에 나눔스퀘어라운드 ExtraBold를, 나머지 글자에 Pretendard를 씁니다. 설정의 “화면”에서 “말랑”(주아), “깔끔”(Pretendard), “통통”(Bagel Fat One), “휴대폰 글꼴”로 바꿀 수 있고, 공유 화면도 같은 글씨를 따릅니다. 한국어 문장은 띄어쓰기에서 줄이 바뀌도록 처리했습니다.
- **사용법 화면**: 처음 실행할 때 한 번 저절로 열리고, 오른쪽 위 메뉴(⋮)의 “사용법”이나 설정에서 다시 볼 수 있습니다.
- **백업**: 설정 화면에서 내 젤리 전체를 JSON 파일로 저장하고 다시 불러올 수 있습니다.

## 공유 젤리와 모두

정한 사람들과 함께 보는 달력입니다. ‘내 젤리’의 일정은 휴대폰 안에만 있고, 공유 달력에 올린 젤리만 서버(Firebase)에 암호화되어 저장됩니다.

- **갤럭시:** 앱 맨 위의 ‘공유 젤리’ 탭에서 엽니다.
- **아이폰:** 사파리에서 `https://ckdgus6068-sudo.github.io/ckdgus6068-sudo/share/`를 열고 ‘홈 화면에 추가’를 누르면 앱처럼 쓸 수 있습니다. 앱스토어용 앱은 애플 개발자 등록과 맥이 있어야 해서 웹 앱으로 만들었습니다.
- **계정:** 처음에 로그인 아이디와 비밀번호로 계정을 만들거나 구글로 로그인합니다. 아이디는 로그인에만 쓰이고 다른 사람에게 보이지 않으며, 달력에서 보이는 이름은 달력마다 따로 정합니다. 새 휴대폰에서 로그인하면 쓰던 공유 달력이 초대 없이 다시 열립니다(구글 계정은 ‘열쇠 비밀번호’를 정해 둔 경우).
- **같이 쓰기:** 한 사람이 ‘새 공유 달력 만들기’를 누른 뒤 메뉴(⋯)의 ‘함께 쓸 사람 초대하기’로 10자리 초대 코드(또는 링크)를 보냅니다. 코드는 3일 동안 여러 사람이 쓸 수 있고, 중간에 거둘 수도 있습니다.
- **여러 달력:** 한 사람이 공유 달력을 다섯 개까지 쓸 수 있습니다(예: 연인, 친구들, 시험용 휴대폰). 제목 아래 달력 이름을 누르면 달력을 바꾸거나 더 만들 수 있습니다.
- **할 수 있는 일:** 젤리를 올리고, 이름·날짜·시간·길이·맛·고정·다 먹음을 달력에 들어온 사람 모두 바로 고칠 수 있습니다. 젤리마다 메모를 주고받을 수 있고, 누가 올리고 고쳤는지 표시됩니다. 앱 안에서는 공유 젤리에도 시작 전 알람을 맞출 수 있습니다.
- **모두 (갤럭시 앱):** 내 젤리와 모든 공유 달력의 젤리를 한 상자(또는 한 달력)에 모아 보여 줍니다. 공유 젤리는 올린 사람의 캐릭터를 입거나, 캐릭터가 없으면 올린 사람의 첫 글자가 동그라미로 붙습니다. 내 젤리는 휴대폰 안의 공유 화면으로만 넘기고 서버에는 올리지 않습니다.
- **오프라인:** 연결이 끊긴 동안 고친 내용은 연결되면 자동으로 올라갑니다.
- **개인정보 안내:** `docs/share/privacy.html` (가입 화면과 메뉴에서 열 수 있습니다).

### 보안 구조

- **종단 간 암호화:** 공유 달력마다 무작위 256비트 열쇠가 있고, 이 열쇠는 달력에 들어온 사람의 기기에만 있습니다. 젤리, 메모, 이름, 색, 캐릭터, 달력 이름은 필드마다 AES-GCM으로 봉인되며, 문서 경로와 필드 이름을 함께 묶어 다른 자리로 옮기면 열리지 않습니다(`docs/share/crypto.js`). 캐릭터는 이름·색과 함께 구성원 프로필 한 값에 봉인되므로 보안 규칙을 바꾸지 않았습니다. 서버와 운영자에게는 사용자 번호, 누가 어느 달력에 있는지, 쓰고 고친 시각, 메모 개수, 암호문만 보입니다.
- **초대:** 초대 코드에서 PBKDF2(30만 회)로 초대 문서 번호와 포장 열쇠를 만들고, 달력 열쇠는 그 열쇠로 포장해 둡니다. 코드 자체는 서버로 가지 않습니다.
- **계정과 열쇠 보관함:** 비밀번호는 기기에서 PBKDF2(30만 회, 아이디가 소금)로 서로 무관한 두 값이 됩니다. 하나는 로그인에, 다른 하나는 열쇠 보관함(`users/{uid}`, 달력 열쇠 목록을 봉인한 것)을 잠그는 데 씁니다. 그래서 로그인 서비스도, 데이터베이스도 보관함을 열 수 없습니다. 구글 계정은 따로 정한 열쇠 비밀번호로 같은 일을 하며, 정하지 않았다면 새 휴대폰에서는 초대 코드를 한 번 더 받습니다. 비밀번호를 잊으면 보관함은 되찾을 수 없습니다.
- **접근 규칙:** `jelly-calendar/share/firestore.rules`. 달력 문서는 그 달력의 사람만 읽고 쓰며, 들어오려면 그 달력을 가리키는 살아 있는 초대가 있어야 하고, 봉인된 값의 크기를 제한합니다. 열쇠 보관함은 그 계정만 읽고 쓰며, 계정 없는(익명) 사용자는 만들 수 없습니다.
- **앱 서명:** APK는 저장소 밖의 비공개 열쇠로 서명합니다(GitHub Actions 비밀값). CI가 인증서 지문을 확인하고, 그 열쇠로 서명된 APK만 내려받기 링크에 올립니다.

### 구조

- 웹 앱: `docs/share/` (빌드 과정 없이 그대로 GitHub Pages로 공개). Firebase SDK는 `jelly-calendar/share/build.mjs`로 묶어 `docs/share/vendor/firebase.js`에 넣었습니다.
- 서버: Cloud Firestore와 Firebase Authentication(아이디·비밀번호, 구글).
- 갤럭시 앱 안에서는 같은 웹 페이지를 띄우고, 앱이 `JellyBridge`로 지금 보여 줄 화면(공유 달력 또는 ‘모두’의 날짜, 그 앞뒤 6주의 내 젤리, 글씨체)을 알려 줍니다. 구글은 웹 화면 안에서의 로그인을 막기 때문에, 앱이 휴대폰의 구글 계정 선택 창(Credential Manager)으로 로그인한 뒤 ID 토큰을 페이지에 넘깁니다.
- 시험: `jelly-calendar/share`에서 `npm ci` 뒤 `npm run test:rules`(보안 규칙 25개), `npm run test:e2e`(두 휴대폰과 새 휴대폰, 계정, 여러 달력, 상자와 ‘모두’, 고정 젤리 늘이기, 캐릭터, 확인 창, 황금 젤리, 구글 로그인 대역까지 67개 확인)를 Firebase 에뮬레이터로 실행합니다. GitHub Actions도 같은 시험을 돌립니다.

### 처음 한 번 설정할 것

1. Firebase 콘솔에서 프로젝트를 만들고 Firestore 데이터베이스를 만듭니다(프로덕션 모드).
2. Authentication의 로그인 방법에서 ‘이메일/비밀번호’를 켭니다. 구글 로그인을 쓰려면 ‘Google’도 켜고, 승인된 도메인에 GitHub Pages 주소(`ckdgus6068-sudo.github.io`)를 넣고, 프로젝트 설정에서 Android 앱(`io.github.ckdgus6068.jellycalendar`)을 등록하며 서명 인증서의 SHA-1을 넣습니다. Google 항목의 ‘웹 클라이언트 ID’를 `app/src/main/res/values/config.xml`에 넣고, 브라우저에서도 쓰려면 `docs/share/config.js`의 `googleSignIn`을 `true`로 바꿉니다.
3. Firestore의 ‘규칙’ 탭에 `jelly-calendar/share/firestore.rules` 내용을 붙여 넣고 게시합니다.
4. 프로젝트 설정의 웹 앱 `firebaseConfig` 값을 `docs/share/config.js`에 넣습니다. 이 값은 원래 공개되는 값이고, 실제 보호는 3번의 규칙과 암호화가 맡습니다.
5. GitHub 저장소의 Settings → Pages에서 Source를 ‘Deploy from a branch’로 두고, 이 브랜치와 `/docs` 폴더를 고릅니다.
6. GitHub 저장소의 Settings → Secrets and variables → Actions에 앱 서명 열쇠 `JELLY_KEYSTORE_BASE64`(PKCS12 파일의 base64, 별칭 `jelly`)와 `JELLY_KEYSTORE_PASSWORD`를 넣습니다.

## 조작 방법

맨 위 ‘내 젤리 · 공유 젤리 · 모두’ 탭으로 볼 것을 고르고, 맨 아래 가운데 “상자 · 주 · 일 · 달” 버튼으로 보기를 바꿉니다. 아래 오른쪽 ‘+’ 버튼으로 새 젤리를 만들고, 아래 왼쪽 ‘오늘’로 오늘로 돌아옵니다. 보관함의 “+ 할 일”로 날짜 없는 젤리를 보관함에 넣어 둘 수 있습니다.

다 먹었어요 방식(두 번 톡, 꾹 누르기)은 설정에서 각각 끌 수 있습니다.

## 삼성 시계 연동 방식과 한계

안드로이드가 다른 앱에 열어 주는 알람 기능은 읽기, 추가, 끄기 요청 정도뿐이라서, 젤리 캘린더도 이 세 가지만 사용합니다.

1. **알람 읽기 (알람 → 첫 일과)**: 휴대폰이 알려 주는 “다음 알람” 한 개의 시각을 읽습니다(`AlarmManager.getNextAlarmClock`). 그 알람이 기상 시간대(기본 03:00–12:00) 안에 있으면 그날의 기상 시각으로 기록하고, “기상 연동”을 켠 반복 젤리를 알람이 울린 뒤 여유 시간(기본 10분)부터 차례로 배치합니다. 반복 젤리끼리의 원래 간격은 그대로 유지됩니다.
2. **알람 맞추기 (첫 일과 → 알람)**: 상자 보기나 일간 보기의 기상 카드에서 버튼을 누르면 삼성 시계에 1회용 알람을 추가해 달라고 요청합니다(`AlarmClock.ACTION_SET_ALARM`). 알람 시각은 “첫 일과 시작 − 여유 시간”입니다. 하루 넘게 남은 날은 ‘날짜 골라 맞추기’를 누르면, 할 일을 안내한 뒤 삼성 시계의 알람 추가 화면을 엽니다(같은 요청을 `EXTRA_SKIP_UI` 없이 삼성 시계에만 보냄). 시각과 이름은 채워져 있고, 날짜는 그 화면의 달력 아이콘으로 직접 골라 저장합니다.
3. **예전 알람 끄기**: 새 알람을 먼저 추가한 뒤, 바뀌기 전 알람(휴대폰이 알려 준 그날의 기상 알람과, 이 앱이 앞서 요청한 알람)을 끄라고 삼성 시계에 요청합니다(`AlarmClock.ACTION_DISMISS_ALARM`, 시각으로 찾기). 1회용 알람은 꺼지고, 반복 알람은 그날 한 번만 건너뜁니다. 새 알람을 먼저 맞추기 때문에 끄기가 실패해도 알람이 사라지는 일은 없습니다. 설정의 “새 알람을 맞추면 예전 알람 끄기”로 끌 수 있습니다.

4. **젤리별 시작 전 알람**: 젤리 편집 창의 ‘더 보기’에서 정각, 10분 전, 30분 전 중 하나를 골라 삼성 시계에 1회용 알람을 추가해 달라고 요청합니다. 앱 안의 공유 젤리에서도 됩니다. 앞으로 24시간 안에 울릴 알람은 바로 추가하고, 그보다 뒤의 알람은 2번과 같이 삼성 시계의 알람 추가 화면을 열어 날짜를 고르게 합니다.

다음과 같은 한계가 있습니다.

- 알람을 지우거나 시각을 고치는 공개 기능은 없습니다. 그래서 “새 알람 추가 + 예전 알람 끄기”로 옮기는 방식을 씁니다. 삼성 시계가 끄기 요청을 받아 주지 않으면 예전 알람은 직접 꺼야 하며, 이때 기상 카드에 안내가 나옵니다.
- 알람 추가 요청에는 날짜를 담을 수 없고, 1회용 알람은 그 시각이 다음에 돌아올 때 울립니다. 그래서 한 번에 바로 맞출 수 있는 알람은 앞으로 24시간 안에 울릴 알람뿐이고, 그보다 뒤의 알람은 삼성 시계 화면에서 날짜를 직접 골라야 합니다.
- 한 번에 알 수 있는 알람은 “다음 알람” 하나뿐입니다. 그래서 며칠 뒤 알람을 저장했는지는 그 알람이 “다음 알람”이 되기 전까지 앱에서 확인할 수 없습니다.
- 알람 목록을 읽을 수 없으므로, 다른 앱이 예약한 알람이 “다음 알람”으로 잡힐 수도 있습니다. 설정 화면에서 그 알람을 어느 앱이 만들었는지 확인할 수 있습니다.
- 확인 필요: 삼성 시계가 “다음 알람” 정보를 제공하는지, “바로 추가” 요청을 확인 화면 없이 저장하는지, ‘날짜 골라 맞추기’ 요청에 날짜를 고를 수 있는 알람 추가 화면을 여는지, 끄기 요청을 받아 주는지는 기기와 One UI 버전에 따라 다를 수 있습니다. 실제 갤럭시 기기에서는 아직 시험하지 못했습니다.

## 설치 방법

휴대폰에서 아래 링크를 누르면 GitHub 로그인 없이 최신 APK가 바로 내려받아집니다.

- 최신 APK: https://github.com/ckdgus6068-sudo/ckdgus6068-sudo/releases/download/jelly-calendar-latest/JellyCalendar.apk
- 릴리스 페이지: https://github.com/ckdgus6068-sudo/ckdgus6068-sudo/releases/latest

1. 링크를 삼성 인터넷이나 Chrome에서 열어 `JellyCalendar.apk`를 내려받습니다.
2. 다운로드가 끝나면 “내 파일” 앱의 다운로드 폴더에서 파일을 누릅니다. 다운로드 알림이나 다른 앱(예: 메신저, Claude 앱)에서 파일을 누르면 설치 화면이 열리지 않을 때가 있으니, “내 파일”에서 여는 방법을 권합니다.
3. “출처를 알 수 없는 앱 설치” 안내가 나오면, 사용 중인 브라우저(삼성 인터넷이나 Chrome)에 설치 권한을 허용한 뒤 설치합니다. Play 프로텍트 경고가 나오면 안내에 따라 설치를 계속 진행합니다. 스토어에 등록되지 않은 앱이라서 나오는 경고입니다.
4. 삼성의 “자동 차단” 기능이 켜져 있으면 설치가 막힙니다. 이때는 설정의 “보안 및 개인정보 보호”에서 자동 차단을 잠시 끄고 설치하세요. 메뉴 이름은 One UI 버전에 따라 조금 다를 수 있습니다.
5. 새 버전도 같은 링크에서 받아 덮어 설치하면 됩니다. 모든 빌드가 같은 비공개 서명 열쇠를 쓰므로 데이터가 그대로 남습니다.
   - 예외: 서명 열쇠를 저장소에 공개된 열쇠에서 비공개 열쇠로 바꾼 첫 버전은 덮어 설치가 되지 않습니다. 이때 한 번만 설정의 **백업 파일 저장**으로 내 젤리를 저장하고, 앱을 지운 뒤 새로 설치해서 **백업 불러오기**를 하면 됩니다.
6. 설치된 버전은 앱 설정 화면 맨 아래(예: “젤리 캘린더 0.2.12”)에서 확인할 수 있습니다. 빌드할 때마다 버전 번호가 올라갑니다.

릴리스는 `main` 또는 `claude/`로 시작하는 브랜치에 코드가 올라갈 때마다 GitHub Actions가 새로 만듭니다. Actions 실행 결과의 Artifacts에서도 APK를 받을 수 있지만, 그쪽은 GitHub 로그인이 필요합니다.

## 데이터 보관

- 모든 데이터는 휴대폰 안의 앱 전용 저장소에 JSON 파일 하나로 저장됩니다. 쓰는 도중에 앱이 꺼져도 파일이 깨지지 않도록 임시 파일에 먼저 쓴 뒤 바꿔 넣고, 직전 버전을 백업으로 한 부 더 남깁니다.
- 휴대폰을 바꿀 때는 설정의 **백업 파일 저장**으로 파일을 만든 뒤, 새 휴대폰에서 **백업 불러오기**를 사용하세요.

## 개발 정보

- `core`: 일정 규칙만 담은 순수 Kotlin 모듈입니다. 반복 젤리 배치, 보관함 이동, 알람 연동 계산, 겹침 배치, 저장 형식을 담당하며 단위 테스트가 있습니다.
- `app`: Jetpack Compose 화면과 안드로이드 연동(삼성 시계, 파일 저장, 백업)입니다. 젤리의 출렁임은 `ui/jelly`에서 외곽선을 점으로 나눈 뒤 매 프레임 스프링 값으로 밀고 당겨 그립니다.
- 빌드 환경: JDK 17, Android SDK 35, AGP 8.7.3, Kotlin 2.1.0, Compose BOM 2024.12.01, 최소 Android 8.0(API 26).
- 빌드 명령: `./gradlew :core:test :app:assembleRelease`
- 서명: 릴리스 APK는 환경 변수 `JELLY_KEYSTORE_FILE`, `JELLY_KEYSTORE_PASSWORD`가 가리키는 비공개 열쇠로 서명합니다(CI가 GitHub 비밀값에서 만듭니다). 열쇠가 없으면 버리는 디버그 열쇠로 서명하며, 그런 APK는 CI가 배포하지 않습니다. 예전에 저장소에 있던 공개 열쇠는 지웠습니다.
- 상자 보기의 젤리는 `ui/box`에서 점을 고리 모양으로 이은 말랑한 물체로 계산합니다(위치 기반 물리, 넓이 유지 제약). 젤리가 여럿 쌓이면 서로 미는 힘 때문에 아주 작게 계속 떨리므로, 30프레임(초당 60프레임이면 0.5초) 동안 어느 젤리도 0.8dp 넘게 움직이지 않는 구간이 두 번 이어지거나 마지막 손길 뒤 900프레임이 지나면 계산을 멈춥니다. 그 뒤로는 상자를 다시 그리지 않습니다. 웹의 공유 상자(`docs/share/box.js`)도 같은 계산과 규칙을 씁니다.

## 검증 범위

- `core` 모듈의 일정 규칙과 저장 형식(고정, 빈 시간 찾기, 공휴일, 황금 젤리 포함)은 단위 테스트 65개로 검증했습니다.
- 공유 젤리는 보안 규칙 시험 25개와 브라우저 종단 간 시험 55개(Firebase 에뮬레이터)로 확인합니다. 서버에 남은 문서를 직접 읽어 이름, 제목, 메모, 날짜, 시간이 평문으로 남지 않았는지도 확인합니다.
- 화면 코드는 데스크톱용 Compose(1.5)로 컴파일하고 실제 글꼴을 넣어 그려서 젤리 모양, 상자 보기, 드래그, 완료 표시, 사용법 화면을 이미지로 확인했습니다. 같은 코드를 Kotlin 2.1 컴파일러로도 컴파일해 보았습니다.
- 안드로이드 APK 빌드는 GitHub Actions에서 수행하고, 안드로이드 에뮬레이터에서 앱을 열어 탭을 차례로 눌러 보며 공유 화면이 제 높이를 받는지(웹 페이지가 기록한 화면 높이)까지 확인합니다.
- 실제 갤럭시 기기에서의 동작(특히 삼성 시계 연동과 손가락 조작감)은 아직 확인하지 못했습니다.
